Vector-ARC: ARC Algorithm

Complete walkthrough of every case in vector_arc_cache.py


ARC Cache T1 · T2 · B1 · B2 O(1) Memory Self-Tuning
1 The Four Data Structures

The entire algorithm lives in four OrderedDict objects. Memorise these.

T1 — RECENCY TIER
Full payload stored
Seen exactly once
LRU evicted first if |T1| > p
T2 — FREQUENCY TIER
Full payload stored
Seen 2+ times
Protected longer than T1
B1 — GHOST OF T1
String key ONLY
Vector & text dropped
Ghost hit → p increases
B2 — GHOST OF T2
String key ONLY
Vector & text dropped
Ghost hit → p decreases
|T1| + |T2| ≤ c   ·   0 ≤ p ≤ c   ·   |T1| + |B1| ≤ c   ·   |T1|+|T2|+|B1|+|B2| ≤ 2c
💡
p is the boundary slider. It is an integer from 0 to c that represents how many slots T1 "should" ideally have. If |T1| > p, the algorithm prefers to evict from T1. The magic of ARC is that p self-tunes — no human needs to set it.
2 get() — Cache Lookup (2 outcomes)
def get(self, key: str) -> Tuple[bool, Optional[Any]]:
    if key in self.t1:
        payload = self.t1.pop(key)
        self.t2[key] = payload    # Promote: recency → frequency
        return True, payload

    if key in self.t2:
        payload = self.t2.pop(key)
        self.t2[key] = payload    # Move to MRU position
        return True, payload

    return False, None
✅ HIT in T1 CACHE HIT

Meaning: This query was seen once before. Now seen a second time → it's "frequent".

Action: Pop from T1, insert into T2 (MRU position). Return payload.

[A*, B, C]
*hit item
BEFORE T2
[D, E]
↓ after get("A")
AFTER T1
[B, C]
AFTER T2
[D, E, A]
A is now MRU
✅ HIT in T2 CACHE HIT

Meaning: This query is already frequent. Reinforce its position.

Action: Pop from T2 (removes from old position), re-insert at MRU end. Stays in T2.

BEFORE T2 (LRU→MRU)
[D*, E, F]
↓ after get("D")
AFTER T2 (LRU→MRU)
[E, F, D]
D moved to MRU
⚠️
D is now last to be evicted. This is how frequently accessed items survive eviction pressure — they keep refreshing their position.
3 _replace() — The Eviction Engine
def _replace(self, key: str, in_b2: bool) -> None:
    t1_len = len(self.t1)
    evict_from_t1 = self.t1 and (
        t1_len > self.p  # T1 is oversized vs target p
        or (in_b2 and t1_len == self.p)  # B2 ghost → bias toward T2
    )

    if evict_from_t1:
        evicted_key, _ = self.t1.popitem(last=False)  # LRU of T1
        self.b1[evicted_key] = None   # ← KEY ONLY. No vector. No text.
    elif self.t2:
        evicted_key, _ = self.t2.popitem(last=False)  # LRU of T2
        self.b2[evicted_key] = None   # ← KEY ONLY. No vector. No text.
🧠
_replace() makes exactly one free slot. It's called only when we need space before admitting a new item. It never touches the ghost lists except to add to them.
🔹 Evict from T1 (condition: |T1| > p, OR in_b2=True and |T1|==p)

Example: c=5, p=2, |T1|=3, |T2|=2. We need one free slot.

t1_len=3 > p=2  →  evict_from_t1 = True
T1.popitem(last=False)  →  removes oldest (LRU) item from T1
B1[evicted_key] = None  →  ghost recorded, payload DROPPED
🔹 Evict from T2 (condition: |T1| ≤ p AND (in_b2=False OR |T1| < p))

Example: c=5, p=3, |T1|=2, |T2|=3. We need one free slot.

t1_len=2 ≤ p=3  →  evict_from_t1 = False
T2.popitem(last=False)  →  removes oldest (LRU) item from T2
B2[evicted_key] = None  →  ghost recorded, payload DROPPED
💡
self.b2[evicted_key] = None — the value is Python's None. The entire 384-float32 vector (~1.5 KB) is permanently dropped. Only the 16-char hex key string (~65 bytes) survives. This is the O(1) memory claim in one line of code.
4 put() — All 6 Cases Exhaustively
CASE 0: Key already in hot cache EARLY RETURN
if key in self.t1 or key in self.t2:
    return  # No-op

When: The coordinator calls get() first. If HIT, put() is never called. This guard is a safety net in case it's called anyway.

Why no duplicate: OrderedDict keys are unique. Inserting the same key twice would just update the value — but we'd lose the ordering. Better to explicitly return.

CASE 1: Ghost hit in B1 RECENCY GHOST HIT → p INCREASES
if key in self.b1:
    delta = max(1, len(self.b2) // len(self.b1) if self.b1 else 1)
    self.p = min(self.c, self.p + delta)   # T1 target grows
    self._replace(key, in_b2=False)
    self.b1.pop(key)
    self.t2[key] = payload   # Skip T1, go straight to T2

The Math: delta formula

delta = max(1,  ⌊|B2| / |B1|⌋)

Intuition: If B2 is large (many frequency evictions) and B1 is small (few recency evictions), recency misses are rare but important → give T1 a bigger boost. The ratio scales the aggressiveness.

FINAL STEP (all miss cases): New item enters T1 ADMIT
self.t1[key] = payload   # New item starts in recency tier

Every new item's life begins in T1. Only after surviving eviction from T1 and being ghost-hit in B1 does it graduate to T2.

5 Complete Decision Flowchart
put(key, payload) │ ├─ key in T1 or T2? ──YES──► return (no-op) [Case 0] │ ├─ key in B1? ──YES──► [Case 1] │ delta = max(1, |B2|//|B1|) │ p = min(c, p + delta) ← p INCREASES │ _replace(in_b2=False) │ B1.pop(key) · T2[key]=payload · return │ ├─ key in B2? ──YES──► [Case 2] │ delta = max(1, |B1|//|B2|) │ p = max(0, p - delta) ← p DECREASES │ _replace(in_b2=True) │ B2.pop(key) · T2[key]=payload · return │ └─ COLD MISS: │ ├─ |T1|+|B1| == c? │ ├─ |T1| < c ──► B1.popitem(oldest) + _replace() [Case 3A] │ └─ |T1| == c ──► T1.popitem(oldest) (no ghost!) [Case 3B] │ └─ |T1|+|B1| < c: ├─ total == 2c ──► B2.popitem(oldest) + _replace() [Case 4a] ├─ total ≥ c ──► _replace() [Case 4b] └─ total < c ──► (no eviction needed) [Case 5] │ T1[key] = payload ← all miss cases end here
